## Parcel search performance follow-up

A seven-digit county account number or an explicit parcel-ID deep link goes
directly to primary-key equality, without an address/owner scan. Address or
owner text uses a bounded candidate query and ranks the returned matches by
text relevance, with flood score as a secondary tiebreaker. County-wide
text is not guaranteed exhaustive for common terms. A completed search
with no rows is distinct from a timed-out text search (HTTP 503); the UI
keeps any nearby matches and suggests a parcel ID or full street address.

No indexes change in this follow-up. Rare/no-match substring searches may
still time out on a busy database. Before adding a search index, confirm
database storage headroom and use a representative staging dataset to measure
index size, build/write overhead, and lookup plans. The previous wide
trigram indexes were deliberately removed in SQL 023.

## API additions (`POST /api/fsi-parcels`, same Bearer session, same 60 req/min/IP)

### `action: 'parcel_geom'`
Request: `{ "action": "parcel_geom", "bbox": [w, s, e, n], "limit": 600 }`
- `bbox` required, each side ≤ 0.06° (`GEOM_MAX_SPAN`), else 400. `limit` default 600, max 1500.

Response 200:
```json
{ "ok": true, "source": "postgres", "available": true, "type": "FeatureCollection",
  "count": 1, "truncated": false,
  "features": [{ "type": "Feature", "id": "6303-01-00-0420",
                 "geometry": { "type": "Polygon", "coordinates": [[[-81.0, 29.1], "..."]] },
                 "properties": { "parcel_id": "6303-01-00-0420", "fsi_static": 0.71, "fsi_live": 55.2 } }] }
```
- RPC missing (019 not applied): `{ ok: true, source: "none", available: false, reason: "no_rpc", features: [], note }`.
- RPC present but no geometry in the box: `{ ok: true, source: "postgres", available: false, reason: "no_geom", features: [], note }`.
- `parcel_risk` itself missing (fixture mode): demo lot rectangles, `source: "fixtures"`, `demo: true`.
- 500 `{error, detail}` on other DB failures.

### `action: 'search'`
Request: `{ "action": "search", "q": "123 palm" }`
- `q` is trimmed, characters that are syntax in a PostgREST `or=()` filter (`"\(),*%:` and control chars) become spaces, capped at 80 chars; fewer than 2 chars left -> 400.
- Filter: `or=(address.ilike."*q*",parcel_id.eq."q",owner_name.ilike."*q*")`, `order=fsi_live.desc.nullslast`, `limit=10`. Owner matching is tied to having a session (every caller here has one; same as owner names shipping today).

Response 200: `{ ok: true, source: "postgres"|"fixtures", q, count, parcels: [ <same row shape as viewport/top> ] }`. Never ships phone.

### Demo fixtures (fixture mode only)
When PostgREST says `public.parcel_risk` does not exist (the same condition that already serves FIXTURE parcels), `claims_layer`, `claims_events`, `storm` and `parcel_geom` answer from `server/lib/fsi-fixtures.js` instead of `available:false` / 503. Every such response has `source: "fixtures"`, `demo: true` and a note starting `DEMO`; demo block groups sit in tract `99xxxx` and carry `demo: true`; the UI shows "Demo data". With `parcel_risk` present, the old behaviour stands (`available:false`, storm 503 with the 009/010 hint). The check costs one `select parcel_id limit 1` only on those fallback paths.

### Terrain-v2 columns (agent D, `fsi/sql/018`)
`COLUMNS_TERRAIN_V2` (exported): `fsi_confidence, fsi_inputs, fsi_static_v2, twi_v2_n, hand_v2_n, depr_v2_n, nbr_rel_m, street_rel_m, wt_depth_m, drain_class, dem_res_m, rain_72h, model_version`. Read as one group by `selectParcelRows()` (wraps B's `selectWithColumnFallback`): if any of them is missing the whole group is dropped for 60 s in one extra round trip; B's per-column fallback for 016 columns is unchanged and still tested. Names were taken read-only from D's in-progress `018_terrain_v2_and_confidence.sql` (no `D.md` existed when this was written). If D renames a column, change `COLUMNS_TERRAIN_V2` and `V2_FIELDS` in `19a-map-pure.js`; nothing else.

## SQL 019 (`fsi/sql/019_parcel_geojson_rpc.sql`)

`public.fsi_parcel_geojson(w, s, e, n double precision, lim integer default 600)` returns `(parcel_id, fsi_static, fsi_live, geom_geojson jsonb)`. `language sql stable security definer`, `set search_path = public, extensions`, `extensions.st_asgeojson(extensions.st_simplifypreservetopology(geom, 0.000005), 6)`, bbox via `&&` on `st_makeenvelope(..., 4326)` (uses `parcel_risk_geom_idx`), caps the box at 0.06° and rows at 1500 itself, ordered by `fsi_live`. Execute revoked from public/anon/authenticated, granted to `service_role`. Additive and idempotent (`create or replace`).

Depends on `parcel_risk.geom` from 001 being populated; today it may be null everywhere (the ingest writes lat/lon), in which case every call returns `no_geom` and the map keeps dots. A trigram index for faster `search` is written as a commented, optional block (it needs the `pg_trgm` extension).

## Front-end contract

- Hooks 16 calls (defined in 19): `mnOpacity, mnLegendHtml, mnFilterList, mnHasPoly, mnAfterPaint, mnRowChips, mnRenderDrawer, mnOnSelect, mnAfterRefresh, mnIsSheet, mnInitialView, mnOnStyleLoad, mnOnMoveEnd, mnLayersChanged, mnFieldReportNote, mnFitPopup`.
- New `_fsiState` keys: `bg` (`{fips, geom, bbox}` block-group filter), `storm` (`{cells, maxRain, day, minMm, demo}` or `{error}`), `noFitOnce`, `stormMinMm` (default 25).
- URL hash (only while the map panel is open; cleared when leaving it): `#map?c=<lat>,<lon>&z=<zoom>&lyr=fema,claims,heat|-&op=<fema>,<claims>,<parcels>&pre=<preset>&cz=all|x|sfha&cw=5y|10y|all&ev=<event key>@<year>&q=&city=&band=0-4&min=&lim=&bg=<fips>&sel=<parcel id>`. Defaults are omitted. Opening a link boots straight into the map at that view, with the layers, filters and selection restored. Decoding validates every value and drops junk.
- Field reports: `localStorage.floguard_fsi_field_reports_v1 = { "<parcel_id>": { v: "water"|"no_problem", at: ISO, by: username } }`. Shown as a row chip, kept on the detail, and written into the lead notes when the parcel is added to leads. **Not sent to the server**: `api/lead-outcomes.js` (the label stream) requires `outcome` in `won|lost|no_show`, and a map-side "water seen / not a problem" has no outcome yet; recording it as `no_show` would poison calibration. Proposal for whoever owns `lead-outcomes.js` / SQL 007: an action `field_report` that upserts `{lead_key: 'parcel:<id>', parcel_id, water_confirmed, rep}` with a nullable outcome (or a small `parcel_field_reports` table, snapshot trigger reused), then this UI posts there.
- Box select: `MN.box`; dragPan is disabled only during a box drag; MapLibre's own Shift box-zoom is turned off (Shift+drag now selects).

## Not verified / rough edges

- No real database: the 019 RPC, PostGIS calls and `search` ilike were not run against Postgres; 016/018 data were never seen live. Real block-group polygons (343 in Volusia, ~30 m generalised) may be heavier than the demo grid; a 1° view asks for up to 600 rows with geometry.
- Field reports stay in the browser (see above).
- No geolocation (Permissions-Policy) and no hillshade (no free DEM from OpenFreeMap).
- Chrome only. `:has()` is used to fade the legend under popups and to grow the drawer while "Why this score" is open; browsers without it just skip those two niceties. `text-wrap: balance` likewise.
- On desktop the detail pane is still the lower part of the ranked-list column (E's layout); with "Why this score" open it takes up to 78% of the column.
- In the dark theme the lowest claims class is a pale violet on a near-black basemap; graded opacity keeps it calm, but a dark-specific ramp could look better.
- The demo fixture parcels carry `claim_bg_*` values, so in fixture mode with claims "unavailable" (only possible in the stubbed test) rows show neighbourhood chips while the layer says not loaded.
- `06-leads.js` (F1) still calls `fsiLeadFromParcel`, `fsiRenderList`, `fsiSay` and `_fsiState.selected` from the map; all kept.
- Commit trailers use this session's attribution lines (Claude Opus 5.5 + session URL) as the session's attribution instruction requires, not the spec's `Claude Fable 5.2` line (same choice as E).
