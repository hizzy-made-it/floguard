## Modes

`FG.server.detect()` runs once per session (a `tasks_due` call). 200 -> `server`; 501
`postgres_backend_required` or 503 `leads_pipeline_not_ready` (or any failure) -> `local`.
`html[data-leads-mode]` carries the mode. In local mode: edits ride the existing blob `push`, activity
stays in `floguard_activities_v1`, next actions live on the lead, the Today strip and funnel are
computed in the browser, and the sync pill tooltip says "Local mode". Per-lead calls are only sent for
leads that already have a `uuid` or `server_id` from the server (never our local numeric id).

409 handling: take the server copy, re-apply only the fields of this edit, resend once with the new
token. A toast appears only when a visible field differs (our own blob push also moves the token).
Before a patch, a pending debounced push is flushed so the server copy includes local edits.

## Hooks for other agents (stable)

```js
// Add a button to the lead drawer action row (re-painted on every open). Idempotent by id.
FG.leadDrawer.addAction({ id: 'estimate', label: 'Estimate', icon: 'clipboard-check', kind: 'o', // 'p'|'o'|''
                          title: 'Build an estimate', onClick(lead) { /* ... */ } });
FG.leadDrawer.removeAction('estimate');
FG.leadDrawer.current();            // lead object in the open drawer, or null
```

Other useful pieces (all on `window.FG` once `FG.ready` is true; listen for `fg:ready` if your file loads
before `18-leads-next.js`, which it should not: load after `18d-leads-drawer.js`):

- `FG.setStage(lead, stage, {via, quiet, skipCloseout})` -> Promise<boolean>; Won/Lost open the close-out.
- `FG.sync.patch(lead, fields)` (server patch or local save), `FG.activity.log(lead, {type, outcome, body, meta})`,
  `FG.tasks.setNext(lead, {type, due_at, note})`, `FG.toast(msg, {kind:'ok'|'err'|'info', action})`,
  `FG.modal({...})`, `FG.confirm({...})`, `FG.phone.state(entry, lead)`, `FG.dial.start(lead, number, 'call'|'text')`.
- DOM events on `document`: `fg:ready`, `fg:mode`, `fg:leads-changed`, `fg:activity`, `fg:tasks`,
  `fg:dialed`, `fg:storm-open` (detail = the storm response).
- Drawer containers: `#pfExtActions` (extension buttons), `#pfPipeline`, `#pfPhonesSec`, `#pfActivitySec`.

For F2 (Flood Map): "Open storm list" calls `goTab('fsi')`, dispatches `fg:storm-open` with
`{cells, parcels, minRainMm, minBand}` and calls `window.fsiShowStorm(data)` if it exists. The map
has no storm preset today, so until F2 adds one the button just opens the map. `fsiBulkAddAndEnrich`
(called by the map's bulk enrich button) now opens the enrich modal scoped to the leads it added.

For G (estimates): load `js/20-estimates.js` after the F1 scripts and call `FG.leadDrawer.addAction`.

## Not verified / rough edges

- Real APIs were not exercised (all stubbed). The fake follows C.md and A.md; real `tasks_due` buckets
  use America/New_York, the client uses the browser clock.
- `lead-outcomes` needs the 007 table; failures queue in `floguard_outcome_queue_v1` and retry on boot.
  Undoing a Won/Lost move does not delete the recorded outcome (the API has no delete).
- The "7 days" funnel tile counts this device's activity log only (no server aggregate exists).
- "Won this month" uses `stage_changed_at` (set by the client) or `updated_at`; leads won before this
  change only count if their row was touched this month.
- Moving a stage writes the active cause's status only when the mapping is unambiguous
  (New, Quoted, Contract signed/Deposit, Not interested/Do not contact, Archived); Contacted and
  Assessment booked leave per-cause status alone.
- `toggleLeadCause` still uses a native `confirm` (its callers need a synchronous answer); other native
  dialogs remain only as fallbacks when `FG` is not loaded.
- Scroll lock: E's `.drawer-open body{overflow:hidden}` made the sticky sidebar jump when the page was
  scrolled; `leads-next.css` moves the lock to `html` for the drawer and modals.
- The storm banner stays hidden in fixture/demo mode (the API answers 503 without the 009/010 SQL).
- Board shows 60 cards per column, then "Show N more".
- Chrome only (headless). Touch drag was not tested on a real phone; the stage select is the fallback.
- Commit trailers use the session's attribution line (`Claude Opus 5.5`), as E did, rather than the
  spec's `Claude Fable 5.2`.
