## Contract for R2: `POST /crm/api/lead-outcomes` (session Bearer token)

```
{ action: 'field_report', parcel_id: '6303-01-00-0420', report: 'water_confirmed' | 'not_a_problem' | null,
  lead_id?: string, note?: string }
```
- `report` also accepts F2's local values `'water'` / `'no_problem'` (and `v` instead of `report`). `null`, `''` or
  `'clear'` withdraws this rep's report (the toggle-off case).
- `parcel_id`: letters, digits, `. _ - /` and space, 1-40 chars, else 400.
- One live report per (parcel, rep). `rep` = session username (body `rep` ignored). `lead_id` / `note` only overwritten when sent.
- 200 `{ ok: true, withdrawn: false, report: {id, parcel_id, lead_id, report, note, rep, reported_at, updated_at, withdrawn_at} }`
- withdraw: 200 `{ ok: true, withdrawn: true|false, report: <row>|null }` (false = nothing to withdraw)
- 400 `{error}` bad input; 401; 429; 503 `{ error: 'field_reports_not_ready', hint }` until 021 is applied (keep the
  local copy and queue/retry, like the outcome queue).

```
{ action: 'field_report_list', parcel_id?: string, parcel_ids?: string[<=200], mine?: true }
```
-> 200 `{ ok, count, reports: [<row>, ...] }` live reports, newest first (max 500). One of the three selectors required.

Calibration: `\copy (select * from parcel_field_report_labels) to 'field_reports.csv' csv header`, then
`python -m pipeline.calibrate ... --proxy field_reports.csv --target water` (label 1 = water, 0 = not a problem, weight 0.8;
concatenate with `proxy_labels.py` output under one header to use both). Not written to `lead_outcomes`.
