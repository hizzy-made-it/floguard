# Handoff R2: integrated front-end review and fix pass (`public/crm/`)

Branch `crm-next/R2`, off the merged E + F1 + F2 + G front end. Front end and `tests/ui` only: no files
under `api/`, `server/`, `scripts/`, `fsi/`; no new dependencies; no API contract changes; every element
id and data attribute other code uses is still there. R1's backend contracts (field reports, daily
enrich cap, litigator on estimate send, list cursors, DNC history) are coded against defensively, so
the branch works before and after R1 merges.

## How it was reviewed

`tests/ui/r2-walkthrough.mjs` drives the whole app with every `/crm/api/*` call stubbed
(`stubAll` in `tests/ui/lib/crm-harness.mjs`: fake Postgres leads API, enrich, the full `fsi-parcels`
contract from the demo fixtures shaped by the real API helpers, drafts, admin, chat, and estimates
through the real handler on the fake Supabase). It covers 1440x900, 1024x768 and 390x844, light and
dark, server mode and local mode (501), the login screen, the proposal page and print, and records
overflow, map coverage, touch-target sizes and first-load weight in `metrics.json`.

```bash
PLAYWRIGHT_CORE=/tmp/etools/node_modules/playwright-core node tests/ui/r2-walkthrough.mjs before|after
```

Screens: `docs/handoff/R2-screens/before/` and `after/` (a curated subset is committed; the full runs
are ~150 MB and are regenerated by the command above). Three after passes were run and looked at.

## What changed (by severity)

Critical
- Closing the estimate editor left its overlay on screen, invisible, eating every click until reload
  (`.est-bg{display:flex}` beat the `hidden` attribute). Global `[hidden]{display:none!important}`;
  the per-component copies were removed.
- Estimate editor on phones laid out at 663px inside a 390px screen (nested grids sized to content).

High
- Flood map: the map started at y=270 (52% of 1440x900) and y=605 on a phone (28%). Now one toolbar
  row (presets, data source, status, Filters popover with score/size/overlays, load buttons) plus the
  claims row (folded into Filters below 1100px and on phones): 67% at 1440x900, 68% at 1024x768,
  64% at 390x844.
- Parcel detail on desktop is a side sheet over the ranked list (Esc returns to the list).
- Basemap failure (offline, tile host down) left the map and the ranked list empty and printed a raw
  `AJAXError`. Falls back to a plain style; parcels and the list still load.
- Storm banner "Open storm list" opened the map but not the Storm list (`window.fsiShowStorm` existed
  nowhere). Wired.
- Estimate sent/accepted did not update the lead's stage, board card or timeline without a reload.
  The editor pulls changed leads after send and when it sees accepted/declined estimates.
- "Report wrong" never reached the server. It now POSTs `field_report` (and `report:null` to
  withdraw); anything not acknowledged `{ok:true}` (503 `field_reports_not_ready`, 4xx, offline)
  stays queued and retries on boot / `online`. Other reps' reports show from `field_report_list`.
- Map "Add to leads" duplicated a parcel already in leads and carried the flood/claims numbers only
  as note text. Now dedupes by `parcel_id` and copies `fsi_live`, `must_have_*`, zone, soil,
  `claim_bg_*`, terrain-v2 fields and the field report onto the lead.
- Leads table with 2,000 leads: 370-450 ms per render, 102k DOM nodes. Pages of 150 with Show more /
  Show all: 38-61 ms, ~9k nodes.
- MapLibre (1 MB JS + 70 KB CSS) was render-blocking on every page; it now loads on first map open.

Medium
- Every lead without a website showed a red "HOT" score (website-sales logic). The score column shows
  the map flood score; otherwise a muted dash.
- Drawer action bar wrapped to three rows with Estimate alone on the last. Now Call / Text / Email /
  Estimate / More (Coach, Queue draft, copy, website, maps) on one row.
- Two modal systems looked different; estimate modal now uses the same scrim token, traps Tab and
  Esc closes only the top layer (menu, confirm, estimate editor, then drawer).
- Native `alert/confirm/prompt` replaced: admin PIN (`FG.prompt`, password field), admin/drafts/
  review/mgmt messages (`fgNotify` toasts), last-cause archive and chat clears (app confirm).
- Dark basemap: dark-specific claims ramp (dark to bright) for all / Zone X / SFHA.
- Enrich modal shows the team's daily paid-lookup cap and stops when `daily.granted === 0`.
- Estimate send treats `phone_litigator` (warning or `message.to`) like DNC: no Messages link, reason
  shown; the local phone state is also honoured.
- Leads header: denser funnel/Today, one-line subtitle, Google Maps capture moved below the list,
  small laptops start on the icon rail; list starts at y~680 instead of 780 at 1440x900.
- Developer copy removed from user-facing text: `leadagent score`, `npm run …`, `fsi/sql/0xx`,
  `fixtures`, `backend postgres`, catalog file paths, `[object Object]`, `FrenchDrain` keys.
- Cache busting: every css/js on `index.html` and `proposal.html` carries `?v=<sha256 prefix>`
  generated by `tests/ui/stamp-versions.mjs`; `tests/ui/versions.test.mjs` fails when stale.

Low
- Admin user detail and docs error printed server strings unescaped (`fmtNum` also passed strings
  through); escaped. Drafts buttons were double-submittable; guarded.
- Phones: 44px minimum touch targets on coarse pointers; map tools moved clear of the zoom control.
- Duplicate leads column widths in `app.css` removed; `--scrim` and `--z-*` tokens added.

## Native dialogs still present
Only fallbacks that run before the FG layer has loaded (no synchronous answer is required anywhere):
`02-crm-core.js` delete fallback, `06-leads.js` last-cause archive fallback, delete fallback and the
pre-FG enrich confirm, `07-chat.js` `fgAsk` fallback, `fgNotify` alert fallback.

## Tests
`npm test`: 241 (was 238). New: `tests/ui/xss.test.mjs` (payloads in every lead, parcel, search,
draft, admin, activity, enrich and estimate string plus the proposal page; asserts nothing executes,
dial/mail links are encoded, no extra credentials in storage), `tests/ui/r2-integration.test.mjs`
(storm -> Storm list, single Estimate button on the action row, stage sync after send, Esc layering,
litigator send, map -> leads fields + dedupe, field_report 503/recover/withdraw + team list, daily
enrich cap, replaced DNC number blocked, paging), `tests/ui/versions.test.mjs`. `map-next.test.mjs`
opens Filters on phones before using the claims controls.

## Not done / not verified
- Map interaction with 2,000 parcels and the board drag code (layout thrash) were not measured.
- Session expiry (401) and the sync chip were not walked panel by panel.
- Dark theme contrast was checked by eye only, not with a contrast tool.
- Coach, roleplay, review, playbook, models and admin got copy and safety fixes, not a redesign.
- Chrome only; no real phone; no real APIs.
- Leads list `since`/`cursor`: the client echoes server `updated_at` values (lead timestamps) and does
  not invent its own; it was not changed.
